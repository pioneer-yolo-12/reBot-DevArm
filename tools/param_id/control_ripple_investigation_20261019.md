# J1～J3 与 J4～J6 控制链路及纹波来源排查

日期：2026-10-19。对象：当前代码、Motorbridge 0.5.6 实际加载库、厂家 CAN2.0 手册，以及 2026-10-16 两轮完整 J6 多速度日志。本轮没有打开真实 CAN 接口，也没有发送实机命令；SDK 编码验证使用拦截全部 AF_CAN socket 的模拟传输。

## 当前可以得出的结论

1. 六轴使用相同的类型 1 五参数运控控制结构，没有 J1～J3 使用速度模式、J4～J6 使用位置模式的分支。
2. SDK 确实按型号采用不同的量程；实际加载二进制的模拟帧验证未发现 RS00/RS06 量程混用、大小端错误或增益扩大 10/20 倍。
3. J6 的角度周期现象同时存在于位置跟踪误差、位置求导速度和反馈力矩，不能仅用速度反馈噪声解释；但位置及其导数都来自同一编码器，尚未独立证明输出轴的真实运动幅度。
4. 在已有两轮日志中，重力前馈、命令位置量化、两类反馈混合和持续控制阻塞都缺少作为主导周期来源的证据。偶发发送迟到仍存在，不能据此宣称实时性或总线没有任何问题。
5. 反馈力矩波形大部分可由 PD 纠正项重现。它不是独立测得的外部摩擦或齿槽转矩，不能直接取其周期幅值作补偿。
6. 目前尚不能在电角度相关转矩扰动、编码器/速度估计误差、闭环放大和机械传动因素之间作最终归因。既有数据的主动扫动轴只有 J6；不能声称 J1～J3 已在相同低速条件下通过，也不能将 J6 结论直接推广到 J4/J5。

## 控制结构核对

主入口 `run_phase2_pointmatch.py` 使用 `friction_id/common.py` 的配置，启动时逐轴 `ensure_mode(Mode.MIT)`，每周期依次发送六轴目标。`MotorSession.send()` 为所有轴计算重力前馈并发送 `send_mit(q_ref, qd_ref, kp, kd, tau_ff)`。

这里 Python 的 MIT 名称映射到 **RS 私有扩展帧运控模式**，并非另一个标准帧 MIT 协议。SDK 中另有 `robstride_mit` 厂商后端；本项目调用的是 `add_robstride_motor`，没有使用该后端。

厂家给出的运控关系：

```text
t_ref = kp*(p_set-p_actual) + kd*(v_set-v_actual) + t_ff
t_ref → 内部力矩/电流转换 → 电流环 → 电机
```

因此当前并非带速度积分器的专用恒速模式。即使 qd_ref 恒定，也不能保证实际速度恒定；同样的控制结构在不同惯量、摩擦、内部滤波和增益下可能表现不同。`spd_kp/spd_ki` 等专用速度环寄存器不能直接当作本次 MIT 的 kp/kd，不能通过只调整它们就认定修复了运控问题；具体内部滤波复用仍须厂商确认。

## 从原始日志逐层排查

复核文件：`friction_20261016_172447_b4729f07.npz` 与 `friction_20261016_172702_03e23883.npz`。均完整，主动扫动轴为 J6，kp=25、kd=2，速度 .07/.10/.15 rad/s，各两次往返。完整数值见 [raw_control_audit.json](realrobot_data/control_audit_20261019/raw_control_audit.json)，图见 [control_ripple_audit.png](realrobot_data/control_audit_20261019/control_ripple_audit.png)。

### 主机发送没有反复停车

按同一运动段统计，排除段间故意的 0.5 s 保持：两轮 J6 发送间隔中位数约 10 ms，p99 约 11.66/11.67 ms，最大 20.95/20.69 ms，每轮各一次超过 20 ms。没有每隔一个纹波周期发生一次的长时间停止发送。接收帧到 Python 读取的延迟 p99 约 1.01/1.02 ms。

这些是主机 API 和内核 RX 时间，不能当作线上 TX 时间或电机执行时间，也不能证明驱动器内部没有延迟。历史 NPZ 导出争用 GIL 的问题与当前完整日志里的持续角度纹波分开判断。

### 两类状态帧不是该纹波的主要制造源

类型 2 应答与类型 24 主动上报单独拟合同一已冻结位置周期，两类的力矩幅值中位数分别约 .2517/.2523（训练）、.2721/.2727（独立运行）；相位差中位数约 .004 rad。两类都具有该纹波，混合两路并非产生它的必要条件。

### 位置也存在大于一个量化步长的周期偏差

位置协议分辨尺度约 `4π/32767=0.0003835 rad`。目标速度 .10 时，两轮跟踪误差的角度谐波幅值中位数约 .00551/.00624 rad，是约 14～16 个协议步长。目标位置量化误差同周期幅值约 .00000261 rad。

因而单纯“反馈位置台阶或目标打包量化”不足以解释该幅值。但编码器的系统角度误差可能远大于一个 LSB；从该编码器求导不能排除这类误差。较短求导窗口得到的速度峰值受平滑方法影响，图示仅作诊断。

### 重力前馈不是主导同周期输入

J6 反馈力矩的同周期幅值约 .22～.28（未标定协议尺度）；已记录重力前馈的同周期幅值低于 .000001，整段变化约 .000109。两者数量级相差很大，当前日志不支持“主机重力前馈主动注入了这条周期波形”。这不证明真实重力模型或实际负载已标定准确。

### 速度反馈噪声不是腕部独有

J6 扫动时，保持轴 J1～J5 每段编码器范围的中位数都约一个位置步长，但其直接上报速度 RMS 分别约 .058～.064（J1～J3）和 .031～.033（J4/J5）rad/s。位置求导 RMS 小得多，但也含量化噪声。

这说明直接上报速度不适合单独作为低速匀速验收或折叠停稳标准，也不能凭当前数据将速度噪声归为仅 RS00 存在。**上报速度噪声不等于内部 D 项使用同一噪声信号**，内部滤波需要进一步核查。

### 反馈力矩很大程度上是闭环纠正的结果

用每帧之前最后一条主机发送完成的指令构造：

```text
tau_pd_proxy = kp*(q_ref-q_fb) + kd*(qd_ref-qd_fb) + tau_ff
```

它与 tau_fb 的分段相关系数中位数约 .907/.916。反馈力矩周期幅值约 .252/.273，代理量约 .257/.278；相减后同周期幅值约 .015/.016。

该代理量不是内部 PD 的精确读数：主机接收状态、内部执行与滤波存在未知时延。因此不能把相减余量直接解释为摩擦。但结果足以说明，不能把整个 tau_fb(q) 周期波形视为独立的外力矩证据，更不能直接将其反相叠加去抵消。完整统计见 [pd_proxy_audit.json](realrobot_data/control_audit_20261019/pd_proxy_audit.json)。

## 根因候选与区分方法

| 候选 | 现有支持与不足 | 最有区分力的下一项检查 |
|---|---|---|
| 电角度相关转矩扰动，包括换相/初始化误差等 | 多速度角周期稳定且接近 RS00 一电周期；未测独立轴角、Iq 或力矩，不能直接命名为齿槽转矩 | 固定条件换起点；同步独立轴角、编码器和 Iq；厂商核查初始化及换相配置 |
| 编码器周期误差或速度估计误差进入 P/D | 位置和速度同源，PD 与反馈力矩高度相关；尚无独立传感器 | 外部编码器或带标尺/标记的光学测量，先确认真实输出轴运动，再比较两套角度的误差是否周期重复 |
| 闭环增益/滤波放大 | 型号、增益及机械负载不同；历史 kd=2→2.5 未消除纹波 | 保持载荷/温度，单变量有限范围对照，同时记录误差、Iq、位置和峰值；不要边改 kp 又改 kd |
| 机械摩擦、齿轮或线缆周期负载 | 低速不匀可由这些因素产生，但电周期接近本身不能排除机械因素 | 确认真实运动后，比较方向、绝对角度与固定线缆布置；必要时在有支撑条件下做隔离实验 |
| 主机轨迹、量程或前馈错误 | 当前帧验证、量化及日志统计不支持其为主导来源 | 后续必要时抓取实际总线 TX 帧，不能以当前“主机调用记录”替代线上抓包 |

1. 六轴只读配置核对：设备/固件、run_mode、当前位置和故障、current kp/ki/filter、速度滤波、初始化及补偿开关，留存所有原始回复。旧调试地址的零值不能当作有效结论。确认接口可读前不使能。
2. 完成已有 J6 0 与 .02 rad 起点对照，仍固定 kp=25、kd=2、速度 .10、原载荷及线缆。不更改编码器零点。
3. 同步一个独立的输出轴运动参考，区分“轴真的卡顿”与“测量误差驱动闭环”。若只能追加 Iq，仍须说明它不能单独提供独立轴角真值；0x701A 是 Iq，0x701B 才是速度。
4. 在确认行程和支撑后，对 J4/J5 及至少一个 RS06 轴采集匹配低速数据，覆盖正反向与多速度。对比是否分别接近各型号电周期；不能从当前保持轴数据替代该对照。
5. 依据以上证据决定处理驱动初始化/测量/增益还是机械问题。之后才做力矩标定、摩擦辨识和补偿，不用新增拟合项掩盖尚未定位的控制问题。

所有运动均保留折叠 → HOME 启动，以及 HOME → 折叠零位 → 停稳确认 → 失能的退出要求。当前没有完成上述新实机对照，因此本报告是已缩小范围的排查结论，不宣称物理根因已经彻底查明。

### 无载条件的解释与下一项对照

无外载降低了外部重力和阻力要求，但转子、减速器和腕部仍有惯量与内部摩擦；编码器/速度估计误差进入 PD 也不需要外载。低惯量下同样的转矩误差会产生更大加速度，这只是机制解释，不能用来判定本次成因。重负载轴可能更平稳，也不能反推腕部应降低到当前增益。

因此下一项优先级调整为：先准备明确的原驱动 PD 对照配置和对应限值，维持当前轨迹、频率与零摩擦补偿，从 J6 做单变量增益对照，再比较是否显著改善位置误差和速度波动。原驱动配置作为对照来源，不一次将六轴全部切换，也不把“增益变大”当作完成修复。若原 PD 下仍保留相同角周期，继续换起点、独立轴角和内部测量检查；即使运动改善，也仍需辨识残余纹波及验证力矩单位。
